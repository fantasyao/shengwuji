# SenseVoice 上下文纠错模块——评估结论与实施方案

## 一、对外部方案的评估

**结论：方案整体适配，核心思想（词库出候选、上下文定答案、用户历史弱先验、低置信不改）正好补齐现有纠错的最大缺陷。** 现有 `CorrectionLearner` 是"会学习的盲替换表"：应用侧 `matchCorrectionPairs`（db_helper.dart:629）裸 `contains`、`applyCorrections`（correction_learner.dart:203）全文 `replaceAll`，一旦学到「质朴=智谱」任何语境都会误伤。需做 5 处适配：

1. **ASR 置信度一项删掉**——sherpa_onnx 离线结果无置信度字段，评分公式该项恒为 0，不影响整体设计。
2. **中文分词不需要引入**——上下文词表是封闭集合（domain_words 的 related/conflict ∪ 共现统计表中的词），直接在窗口内做已知词子串扫描，信息无损且零依赖。
3. **一期只做 bigram 共现**（带距离权重），不做 trigram；只在候选词命中时才查库，库体量 KB 级。
4. **与现有 correction_pairs 的冲突处理（关键）**：学习提取出的纠错对若属于同一同音组（如 质朴↔智谱），**改道写入共现统计+词频，不再进盲替换表**；否则两套机制互相打架。
5. **只学用户明确行为**（方案§18）：现有 `_learnFromEdit`/SnackBar 采纳机制天然满足，直接在其上挂钩，不加自动学习。

现有热词、修正对提示、学习机制全部保留不动，新模块是叠加的上下文层。

## 三、数据库（items.db v11→v12）

照 v11 模式在 **onCreate 与 onUpgrade 双写**相同建表语句 + try/catch：
- `correction_context_stats(source_word, context_word, count, PK(source_word, context_word))`
- `correction_user_words(word PK, frequency, last_used_at)`

DbHelper 新方法（照抄 learnCorrectionPairs 的事务+OFFSET 淘汰模式）：`bumpCorrectionContextStats`、`getAllCorrectionContextStats()`→Map、`bumpUserWord`、`getAllUserWords()`→Map，统计表超 3000 行按 count 淘汰。方案里的 correction_history 表**不建**——correction_pairs 已承担该职责。

## 四、接线（5 条转写链路 + 学习点）

自动修正（均在 TextProcessor 之后插入一行 `correct()`）：
- `diary_tab.dart:1903` `_processRecognizedText`（ListExtractor 之前）
- `record_tab.dart:539`（录入页填框前）、`record_tab.dart:987`（搬家模式，即时落库场景收益最大）
- `overlay/overlay_voice_memo.dart:426`（悬浮窗速记，独立 engine 共享同一 SQLite 文件，现有 correction_pairs 已验证跨 engine 可行）
- `list_tab.dart:338`（语音搜索）

学习（`_learnFromEdit` 三处 + SnackBar 采纳两处，共 5 个调用点改走 ContextLearner 分流）：
- `record_tab.dart:642`、`diary_tab.dart:2001`、`overlay_home.dart:982`、record_tab:694 采纳、diary_tab:2034 采纳
- 防打架守卫：`_offerCorrectionFix` 匹配时过滤掉"error 与 correct 同属一个同音组"的修正对（含 txt 导入进来的），这类对只由上下文模块处理。

设置页（settings_tab）：加一行开关「同音词上下文纠错」（仿 move_mode_tts_enabled 的 Switch 行）；已有「修正对管理」入口不动。备份 ZIP 一期不含共现统计（属可再生先验，后续可选）。

## 五、测试（flutter_test，纯逻辑注入依赖，不碰 sqflite）

1. `test/context_scorer_test.dart`——分项计分、距离衰减、动态共现封顶、阈值判定。
2. `test/context_corrector_test.dart`——方案§20 验收用例集（喂错误变体）：
   - 应改智谱：质朴公司 / 质朴AI / 质朴的GLM模型 / 质朴发布了新的模型 / 我最近在研究质朴 / 质朴的大模型
   - 应改质朴：这个人很智谱 / 他的性格非常智谱 / 这个女孩看起来很智谱 / 他为人智谱真诚 / 我喜欢这种智谱的感觉
   - 防误改：孤立"质朴/智谱"无上下文不动、"我同意你的看法"不动、"他用深度搜索查资料"已对不动、"这个人性格非常质朴"已对不动；同文多次命中逐位置独立处理
   - 动态统计生效：伪造 stats（智谱+公司×3）后孤立句可改
3. `test/context_learner_test.dart`——同音组对进统计不进替换表、普通对照旧、上下文词取自编辑后文本窗口、纯插入/删除对不产生统计。

调参方式：以验收用例集为规格，把 MIN_SCORE/MIN_MARGIN 和词表调到"应改用例裕量≥20、防误改用例全部不触发"，常数固化进 correction_config.dart。

## 六、验收

- 新增测试全绿；`flutter analyze` 零 error；现有 184 个用例无回归。
- 行为不变项确认：热词替换、修正对提示/学习、悬浮窗流程、搬家模式撤销命令均不受影响（撤销关键词与同音词表无交集）。
- 新增体积：两个 KB 级 json + 两张小表，符合"KB～几 MB"约束；无网络、无新模型。
