## 第四轮修复（本次）：根因定论与根治方案（2026-08-29）

### 两个新确诊缺陷（第三~三轮 b 未根治的真正原因）

1. **挂门晚于 resize 发出，摘门依赖"约束变化检测"有时序缺陷**：揭示门在 `onStartVoiceMemo` 的 `await _voiceMemo.start()` 之后才挂上，而 `_voiceMemo.start()` 尾部的 notifyListeners 会同步触发 `_onVoiceMemoChanged` 发出 `resizeOverlay(312,64)`——即 **resize 先于挂门发出**。若原生 resize 在挂门后的首个 build 前已落地（viewport metrics 已回传），lazy 基准补记到的首个观测约束就是**胶囊尺寸**本身，"size != 基准"永不成立 → **门永不摘**、voiceMemoUiReady 永不发出（靠转写态防御摘门兜底），时序完全错乱。
2. **挂门前的把手帧已进入渲染管线，空白门盖不住**：挂门前的 await 链（权限/prefs/开流，约 20~80ms）期间 state 仍是 idle，初始 collapsed 态的把手帧已在挂门之前完成构建并进 SurfaceFlinger buffer queue——挂门后的空白帧只能保证"之后的帧没有把手"，管不住"已经在管线里的把手帧"。这解释了第三轮 b"挂门期渲染空白却仍闪"。

### 用户录屏证据与竞态定性

- 用户屏幕录制慢放确认：闪现物就是"记一笔"把手本身（排除窗口背景色/resize 形变假设）
- `bc3a826`（语音速记诞生前的锚点提交）时代同路径零闪现；锚点提交到出问题的提交之间，语音速记代码**逐字节零改动**——闪现是既有竞态被整包 AOT 快照变化/时序偏移"翻出"的概率问题，不是新代码引入的确定性 bug。这解释了"同代码同日志两次运行一次闪一次干净"

### 根治方案（不再修赛跑，直接消除赛道）

**语音速记冷启动隐藏窗口直接以胶囊尺寸（312×64）创建**——把手尺寸的窗口在此路径中不存在，无 resize、无把手帧，把手像素物理上不可能出现：

- **Kotlin** `showOverlay(hidden=true)`：`buildOverlayParams(28, 88, hidden=true)` → `buildOverlayParams(312, 64, hidden=true)`（新常量 `VOICE_MEMO_OVERLAY_WIDTH_DP/HEIGHT_DP`，硬编码副本，唯一真值在 Dart 侧 `overlay_constants.dart` 的 `voiceMemoWindowWidth`（新增，= voiceMemoMaxWidth 300 + voiceMemoEdgeMargin 12）/ `voiceMemoWindowHeight`，改尺寸须双侧同步）
- **Dart 挂门提前至 handler 顶部**：`onStartVoiceMemo` 在 `if (!mounted) return;` 之后、`_stopAudioPlayback()` 之前立即挂门（hiddenReveal=true 时）——挂门前的把手帧问题不复存在（窗口已是胶囊尺寸），晚挂门的竞态窗口也一并关闭
- **摘门改为确定性事件**：删除 `_revealGateConstraints` lazy 基准与 `_maybeAdvanceMetricsStage` 的约束变化检测；摘门条件 = build 挂门短路处发现 `_voiceMemo.state != idle`（录音/转写态首帧）——窗口从创建起就是胶囊尺寸，本帧渲染的就是正确尺寸胶囊，构建完（postFrameCallback）发 voiceMemoUiReady
- **硬不变量兜底**（build 顶层，语音速记分支之前）：`state == idle && constraints.maxHeight < handleHeight`（88）→ 渲染纯空白。把手（88dp 高）永远不可能合法出现在胶囊高度（64dp）的窗口里——engine attach 瞬间 / startVoiceMemo 到达前的 pre-gate 帧物理上渲染不出把手
- **Kotlin 揭示延迟 1 → 2 vsync**（Choreographer.postFrameCallback 嵌套两层）：构建完 ≠ 已呈现，光栅化 + SurfaceFlinger 合成可能晚 1~2 vsync，多等一帧是便宜保险
- **保留不动**：`resizeOverlay` 的 `pendingVoiceMemoReveal && width == -1` 防御性顺带揭示；`_onVoiceMemoChanged` 的 `resizeOverlay(312,64)`（暖路径把手→胶囊切换仍需要；冷路径同尺寸 updateViewLayout 幂等无害）；`_onVoiceMemoChanged` 转写态防御性摘门（去掉 constraints 清理行）；`_resetFromNative` 清门

第三轮的 SIGABRT 事故教训（FlutterView 必须 attach）继续有效——本方案仍是"立即 addView + alpha=0 隐藏"，不违反铁律。
