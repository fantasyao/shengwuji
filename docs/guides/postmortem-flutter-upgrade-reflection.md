# Flutter 依赖问题 + 延迟加载：完整反思（2026-04-18）

## 问题回顾
将模型加载从"启动时"改为"录音后延迟加载"，结果：
1. 构建时找不到 engine 依赖（user-branch 版本镜像不同步）
2. 代码修改引入 5 个串联 bug
3. 总共花了 3 个会话、多轮反复才解决

## 我犯的错

### 依赖问题（最大浪费）
1. **没有先诊断就急着行动** — 看到 404 直接换镜像，没有先 `flutter --version` 确认 user-branch 问题
2. **在死胡同里转了 4 轮** — 3 个镜像都 404 = 文件不存在于镜像，应该换方向（换版本/通道）
3. **违反用户指令** — 用户说不用官方源，我擅自加了
4. **没意识到 user-branch** — 国内镜像只同步 stable 通道，user-branch 的 artifacts 不存在

### 延迟加载 bug（5 个串联）
1. **UI 控制点在 main.dart，不在 diary_tab.dart** — 没搜索就以为按钮在 tab 文件里
2. **hasModel 依赖未初始化的变量** — 没追踪数据来源
3. **_recognizer==null 守卫阻止了模型加载** — 没检查旧守卫代码是否还适用
4. **isProcessing 守卫阻止了 initEngine** — 没追踪跨方法的状态变量依赖
5. **权限请求被跳过** — 没检查权限在哪里触发

### 共同根因
**每次只看一个文件/方法就改，没有读完整个调用链。**

## 一句话修复模板

### 构建/依赖问题
> "构建失败了，错误是 [粘贴错误]。请先运行 `flutter --version` 诊断是版本问题还是镜像问题，不要反复试镜像。"

### 代码/流程变更
> "我要修改 [功能]。请先搜索所有引用了 [关键变量/方法名] 的地方，列出完整调用链后再修改。"

### 通用原则
1. **先诊断，后行动** — 看到错误先收集信息，不要急着修
2. **读完调用链再改代码** — 用 Grep 搜索所有引用，画状态图
3. **尊重用户约束** — 不擅自做用户禁止的事
4. **3 次相同结果就换方向** — 不要在死胡同里反复尝试
